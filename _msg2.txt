feat(memory): a shared half in the project repo, and a promote verb

Owner decision 2026-09-21: "das Ziel ist, dass ein Team gemeinsame Infos hat
aber nicht persoenliche", and "nicht neu erfinden, best practices von
erfolgreichen apps". Researched before building, then built to the finding.

THE SPLIT. A note is either personal (db, this machine, never leaves) or
shared (markdown in the user's project repo, travels by git, reviewed like
code). The half IS the place, so one fact never exists twice and a merge
between two copies cannot arise. Crossing the line is an act with an author -
the new `share_note` action - not a sync. That is Notion's shape: private is a
location and moving is the publish act.

WHY A REPO, AND ONLY FOR THIS HALF. Two vendors converged independently:
Claude Code makes a subagent's `project` memory the recommended default and
commits it; Devin is deprecating its hosted Knowledge DB in favour of
SKILL.md files in the repo. And Anthropic keeps agent-WRITTEN auto-memory out
of git on purpose, machine-local. Every documented failure of memory-in-git is
git as an external, credentialed, lock-holding process inside an automated
loop: letta-code#4249, #3705, #4266, #808. We are a Windows daemon spawning
concurrent worktrees, so the personal half stays exactly where it is and
nothing here ever commits or fetches on its own behalf.

PRECEDENCE, copied verbatim from Claude Code: concatenate rather than
override, and read the personal half LAST so it wins. A shared note and a
personal note about the same topic need an order, not a merge.

REFUSALS ARE LOUD, which is the whole point of this card. A knowledge file
with merge-conflict markers, over 20k chars, or unreadable is not loaded AND
is named in the turn's overview - Letta ships a skill to clean conflict
markers up after they reach the model; not letting them in is cheaper.
promote() refuses a note carrying anything credential-shaped, with the reason,
because this half leaves the machine.

The gate gained a fourth check (still light: one directory listing, a no-op
until the directory exists). Brief kept under the 15k cap by compressing the
new text and moving the action detail to actions.md, not by raising the cap.

Registered, not hidden: shared-knowledge-no-fetch (we read the working tree,
nothing pulls - deliberate, with the fix written down) and
personal-memory-does-not-travel (the 86 auto-memory notes rank owner-fact and
have no backup and no path to a second machine; measured while answering the
takeout question).
