# HelmDeck Glance worker — the public HTTPS origin for the glasses

> Read `docs/glasses-reference.md` §11.9 first. It records the correction this
> directory exists because of: **putting our own webapp permanently on our own
> glasses was never gated.** "Publishing is partner-only" is true of the Meta
> *store listing* and says nothing about *Add a Web App*, which is self-serve
> and needs one thing — a public HTTPS URL. This Worker is that URL.

One origin serves **both** the static app and the `/glance` API, so:

- you register **one** URL on the glasses, once, and never touch the device
  again — new screens ship by re-running the deploy;
- the app is **same-origin** with its API, which is not cosmetic: an `<audio>`
  element cannot send an auth header, so `/glance/voice/<id>.mp3` only works
  when it is a relative URL. glass-crud-harness hit the identical wall and
  solved it the identical way (`worker.js:341-344`).

## The security model — read before adding a route

This is the first thing in HelmDeck that puts a door to the owner's daemon on
the open internet, and the daemon behind it serves cards, settings, chat and
driver commands.

**The Worker proxies five paths and nothing else, ever.**

| Path | Method |
|---|---|
| `/glance` | GET |
| `/glance/answer` | POST |
| `/glance/talk` | POST |
| `/glance/photo` | POST (the DAT camera — see the body cap below) |
| `/glance/voice/<id>.mp3` | GET (`id` = alnum, ≤32 — mirrors `daemon/voice.py:63-69`) |

**Body caps are PER ROUTE.** Everything defaults to 64 KB, because a glance
body is a spoken sentence or a chosen option id. `/glance/photo` is the one
exception at 12 MB, and it is an override rather than a raised global on
purpose: raising `MAX_BODY` would also let a 12 MB body be posted to
`/glance/talk` — straight into an agent prompt. `tests/test_glance_worker.py`
asserts that `/glance/talk` keeps the small cap, that an unlisted path falls
back to it, and that a `constructor` lookup cannot inherit one from
`Object.prototype`.

The photo path is safe to expose for two reasons that live on the daemon, not
here: it is OFF unless `settings.glance_photo` is set (its own switch, not
`glance_token`'s), and it refuses without a card id — so it can only attach an
image to a card that already exists, never drop files at the machine.

Anything unmatched is served from static assets or 404s; it never falls through
to the daemon. `Cookie` and `Authorization` are stripped going up — the daemon
also authenticates the desktop UI by session cookie, and forwarding credentials
would turn this into a replay path into an authenticated session. `/glance` auth
is the `glance_token` and only the `glance_token`.

`tests/test_glance_worker.py` executes the real routing function against the
traversal and prefix-confusion cases. Widening `PROXY_ROUTES` widens what the
internet can reach on the owner's machine — do it deliberately, and the test
will tell you if a pattern is looser than it reads.

## Where the token travels

| | carries the token |
|---|---|
| the registered URL | `#t=<token>` — a **fragment**, never sent to any server, lifted into `localStorage` on first load and scrubbed from the address bar |
| `GET /glance` | `X-Glance-Token` **header** — headers are not written to Cloudflare's URL logs |
| `POST /glance/answer` · `/glance/talk` | the JSON **body** |
| `GET /glance/voice/<id>.mp3` | `?token=` — **unavoidable**, an `<audio>` cannot set headers |

The Worker converts whichever form arrives into the `?token=` query the daemon
requires (`daemon/server.py:415-418`). So exactly one route puts the token in a
URL at the edge, and it is the one the platform forces.

This is still the owner's accepted trade: the token passes through third-party
infrastructure. The alternative — replicating the daemon's outbound long-poll
(`relay/relay.py`) in a Durable Object so no inbound origin exists at all — is
sketched in the repo-root `worker/README.md` and is not what this is.

## Setup (once)

```bash
# 1. a Worker at the edge cannot see localhost:8140
bash deploy/cloudflare_tunnel.sh              # prints an https URL

# 2. tell the Worker where the daemon is (a SECRET - a door to the flat)
cd glasses/worker && npx wrangler secret put DAEMON_URL

# 3. turn the endpoint on: settings.glance_token in HelmDeck Settings
#    (plus glance_talk / glance_decide to talk and to decide)

# 4. ship
bash deploy/push_glance.sh
```

Then register **one** URL on the glasses — Meta AI app → Developer Mode → App
Connections → Web Apps → **Add a Web App**:

```
https://helmdeck-glance.<subdomain>.workers.dev/#t=<glance_token>
```

Scan it as a QR from the phone and it is added in one tap
(`fb-viewapp://web_app_deep_link?appName=…&appUrl=…`).

## Layout

```
glasses/worker/
  wrangler.jsonc   # name, assets binding, run_worker_first
  src/index.js     # allowlist proxy + static fallthrough
  public/          # GENERATED by push_glance.sh - git-ignored, do not edit
```

`public/` is synced from `glasses/{index.html,styles.css,app.js}` at deploy
time. Two tracked copies of the app would eventually disagree; the sync is a
build step, exactly like glass-crud-harness's `apps/` → `worker/public/`.

## Local check

```bash
cd glasses/worker && npx wrangler dev
# then, in another shell, with the daemon running on :8140:
#   DAEMON_URL is read from .dev.vars for `wrangler dev`:
#   echo 'DAEMON_URL = "http://127.0.0.1:8140"' > glasses/worker/.dev.vars
```

`GET /health` reports whether `DAEMON_URL` is set — the failure that otherwise
shows up as a blank lens with no clue why.
